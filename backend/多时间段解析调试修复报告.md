### 发现的问题
1. **预约ID为null**: booking对象可能有问题或ID未设置
2. **时间段解析失败**: 实际格式与预期不符
3. **实际格式**: `2025-03-17 14:55:00-15:40:00; 2025-03-18 14:55:00-15:40:00`
   - 分号后有空格
   - 结束时间只有时间部分（无日期）

## 🔧 修复措施

### 1. 增强空值检查

**修复前**:
```java
log.info("开始为预约创建课程排课记录，预约ID: {}", booking.getId());
```

**修复后**:
```java
if (booking == null) {
    log.error("booking对象为null，无法创建课程排课记录");
    return;

log.info("开始为预约创建课程排课记录，预约ID: {}, 预约名称: {}",

```

### 2. 优化时间段解析逻辑

**核心问题**: 原解析逻辑无法正确处理 `"2025-03-17 14:55:00-15:40:00"` 格式

**修复策略**:
```java
// 智能识别结束时间格式
if (endPart.length() <= 8) {
    // 只有时间部分，使用开始时间的日期
    endTime = LocalDateTime.parse(startTime.toLocalDate() + " " + endPart, formatter);
} else if (endPart.matches("\\d{4}-\\d{2}-\\d{2} \\d{2}:\\d{2}:\\d{2}")) {
    // 完整的日期时间格式
    endTime = LocalDateTime.parse(endPart, formatter);
}
```

### 3. 增强调试日志

**新增详细日志**:

```java
log.debug("开始解析时间范围: [{}]", timeRange);

```

### 4. 增强容错处理

**多层次解析**:
1. **优先**: 简单的 `startDateTime-endTime` 格式解析
2. **备用**: 正则表达式匹配完整时间
3. **兜底**: 基础字段fallback

## 🚀 功能增强

### 支持的时间格式
```java
// 格式1: 分号+空格分隔，结束时间仅时间部分
"2025-03-17 14:55:00-15:40:00; 2025-03-18 14:55:00-15:40:00"

// 格式2: 分号分隔，结束时间完整
"2025-03-06 08:55:00-09:40:00;2025-03-05 08:55:00-09:40:00"

// 格式3: 跨日期完整格式  
"2025-03-06 08:55:00-2025-03-05 09:40:00"

// 格式4: 单时间段
```
