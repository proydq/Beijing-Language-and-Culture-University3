# 用户类型字段部署说明

## 修改概述
在用户表中添加 `user_type` 字段，用于标识用户是教师还是学生，解决创建预约时用户类型识别问题。

## 部署步骤

### 1. 数据库修改
执行以下SQL脚本添加用户类型字段：

```sql
-- 位置：backend/src/main/resources/sql/add_user_type_field.sql
ALTER TABLE sys_user 
ADD COLUMN user_type VARCHAR(10) DEFAULT '教师' 
COMMENT '用户类型：教师/学生，用于预约时标识申请人身份';
```

### 2. 代码修改说明
已修改以下文件：

#### SysUser.java
- 添加了 `userType` 字段（默认值："教师"）
- 添加了对应的 getter/setter 方法

#### RoomBookingServiceImpl.java
- 修改了 `buildBookingEntity` 方法，改为从用户表获取用户类型
- 添加了 `getUserTypeFromDatabase` 方法用于获取用户类型

### 3. 功能说明
- **新用户**: 默认用户类型为"教师"
- **现有用户**: 需要手动设置用户类型
- **预约创建**: 自动从用户表获取用户类型，无需前端传入
- **向后兼容**: 不影响现有功能和统计

### 4. 用户类型设置
部署完成后，需要手动设置现有用户的类型：

```sql
-- 设置学生用户示例
UPDATE sys_user SET user_type = '学生' WHERE id IN ('user_id_1', 'user_id_2');

-- 设置教师用户示例  
UPDATE sys_user SET user_type = '教师' WHERE id IN ('user_id_3', 'user_id_4');
```

### 5. 验证方法
1. 检查字段是否添加成功：
   ```sql
   DESCRIBE sys_user;
   ```

2. 创建测试预约，验证 `applicant_type` 字段是否正确设置

3. 检查统计功能是否正常工作

## 注意事项
- 默认值为"教师"，所有新用户将自动设置为教师类型
- 现有用户需要根据实际情况手动设置用户类型
- 只支持"教师"和"学生"两种类型
- 修改不影响现有的统计和业务功能

## 回滚方案
如需回滚，执行以下SQL：
```sql
ALTER TABLE sys_user DROP COLUMN user_type;
```
同时恢复原有的代码文件。
