# 用户类型更新问题修复说明

## 问题描述
用户在编辑用户信息时，修改用户类型后显示保存成功，但数据没有实际变化。

## 问题原因
经过排查，发现有两个用户管理的控制器：
1. `/system/user` - SysUserController
2. `/api/user` - UserController（实际使用的）

前端调用的是 `/api/user/{id}` 的 PUT 方法，对应的是 UserController，它使用 UserSaveRequest DTO 来接收请求数据。

问题出在：
1. UserSaveRequest 类中缺少 userType 字段
2. UserServiceImpl 的 update 方法没有处理 userType 字段

## 修复内容

### 1. UserSaveRequest.java
在 DTO 类中添加了 userType 字段：
```java
private String userType;
```

### 2. UserServiceImpl.java
在 update 方法中添加了对 userType 的处理：
```java
if (StringUtils.hasText(request.getUserType())) {
    user.setUserType(request.getUserType());
}
```

在 create 方法中添加了默认值处理：
```java
// 如果没有设置用户类型，则默认为教师
if (!StringUtils.hasText(user.getUserType())) {
    user.setUserType("教师");
}
```

## 需要的后续操作

1. **重新编译后端项目**
   ```bash
   cd backend
   mvn clean compile
   ```

3. **默认值测试**
   - 如果不选择用户类型，应默认为"教师"
